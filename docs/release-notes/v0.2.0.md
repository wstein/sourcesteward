# SourceSteward v0.2.0: release notes (draft)

**Status: draft for the owner.** Written 2026-10-27 from the pull requests merged after `v0.1.0` (tag commit
`2f246f53`, 2026-10-23, pull requests #172, #173, #175 and #176 to #325) and from the user documentation on `main`
at `ab4c657c`. It is not the generated body of the release: the workflow writes a commit-subject list
(`.github/scripts/release-notes.sh`), and replacing or extending it with this text is the owner's choice, see
[the release protocol](../releasing-v0.2.0.md#d3-release-notes-owner-decision). Every statement below is backed by a file in
the claims table of the pull request that added this page. Nothing here is a promise about later releases.

## Highlights

- `stw tidy` is now a guided, workspace-wide cleanup: a grouped overview, a risk level for every group, and one
  step per group. Enter takes a green group, a yellow or orange group needs a decision, and a red row cannot be
  selected at all.
- `stw sync` can undo a run (`stw sync restore`), can bring pinned submodules to their recorded commits
  (`--submodules`), and merges only when you say `--merge`.
- A narrow, reversible registration prune for stale Git worktree registrations (`--contract 4`), with history and
  restore, in the expert layer of `stw tidy`.
- `stw status` now points to `stw tidy` for unmerged branches and stale worktrees.

## The tidy wizard

Bare `stw tidy` on a terminal reads the workspace and walks you through it ([guide](../tidy.md#the-tidy-wizard)).

- **Grouped overview and retain table.** Candidates are grouped by kind and family and shown with a risk level
  (green, yellow, orange, red or kept), with the reasons in plain words. Rows that are kept or red are listed in a
  separate "Kept" table and are never offered for deletion. `--rows` keeps the earlier row view.
- **Group steps.** Each group shows owner, evidence, effect and how to recover, then asks `take`, `skip`, `list`,
  `review each` or `quit`. Selection accepts numbers, ranges, selectors and `except`. `a` takes every green row of
  every owner. A final summary states how many directories are deleted for good before the typed prompt, which is
  unchanged. The janitor steps only store a plan set; applying it is a separate answer.
- **Online by default for people, offline for everything else.** The human wizard reads GitHub (authenticated,
  github.com only, read requests only, bounded) to recognize work whose pull request was merged; `--offline` turns
  that off, and any failure falls back to offline with one notice. `stw tidy plan`, `--json`, `--save`, agent mode and
  the expert layer stay offline unless you pass `--online`.
- **Observation window.** The per-repository deadline now scales with the number of worktrees and branches (60 s
  plus 1 s each, at most 10 minutes). Items that could not be judged in time are counted ("N of M not judged") with a
  retry hint such as `--timeout 15m`; `--timeout` accepts up to 1 hour.
- **JSON.** `stw tidy plan --json` and `stw tidy --json` gain additive `risk`, `risk_reasons`, `group`, `pr` and a
  per-level `summary`; existing members and their order are unchanged.
- **Safer apply.** Several retirements of one repository now apply in one run, a stale registration with a missing
  directory no longer blocks `plan --save`, and an expired observation deadline is reported as `deadline-exceeded`.
- **Progress output.** One live line per repository, `--verbose` and `--trace`, colors, and a faster analysis
  (#300 reports about three times; #297, #302, #303).

## Registration prune (expert layer)

`stw tidy` (expert layer, contract 4) can remove an owned, locked Git worktree registration whose checkout directory
is missing, and keeps a private recovery payload. `stw tidy restore --contract 4` brings a pruned registration back
and `stw tidy history --contract 4` lists the prunes ([guide](../tidy.md#administrative-registration-restore-contract-4)).
Applying and restoring need `--apply` and `--authorize`, and a typed confirmation for another owner's registration.

## Sync

- `stw sync restore [PATH] [--run ID]` moves the branches of a run back to their journaled old tips, only while they
  still point at the tip the run left and a checked-out worktree is clean.
- `stw sync --submodules` brings the pinned submodules to the recorded commit.
- A run keeps only the ten most recent completed runs of recovery refs and records.
- A stash kept after a failed autostash is journaled and reported.

## Watch, pulls and restack

`stw watch`, `stw pulls` and their sources are unchanged since `v0.1.0`: the diff of `internal/watch`,
`internal/watchcmd`, `internal/pulls` and `internal/pullscmd` between the two revisions is empty. The hidden
`stw restack plan` pins merge attributes to the empty tree so repository attribute files cannot change a plan (#279).

## Upgrade notes

- **Breaking, `stw sync`:** `--no-rebase` and `--no-ff` are gone. A diverged branch is rebased by `--rebase` or a
  rebasing `pull.rebase`, merged only by `--merge`, and otherwise reported as `diverged` and left unchanged. A
  branch that can fast-forward always fast-forwards. `--merge` conflicts with `--rebase` and `--ff-only` (exit 2).
- **`stw tidy` on a terminal** now starts the janitor steps. Scripts and agents should keep using
  `stw tidy plan --json`, which does not prompt.
- The `tidy-overview` JSON schema (`schemas/v2/tidy-overview.schema.json`) is frozen in the source tree but is
  **not published** with this release; treat it as experimental. The sync, status, watch, pulls and issues schemas
  stay unpublished as before.
- `stw` is still shipped for Linux and macOS (amd64 and arm64) only, unsigned and not notarized; verify downloads
  with `SHA256SUMS` and `gh attestation verify` as in the release body.

## Known limits

- **The apply confirmation of the janitor is not finished in this draft.** Pull request #323 (Spec 044 P4b: the
  receipt that lets one typed word cover the apply of the plan stored in the same run, and reading all store and
  apply answers from the controlling terminal) was an open Draft on 2026-10-27. Until it merges, the janitor stops
  after storing the plan set and prints `stw tidy apply PLAN-ID`, which asks again. **Edit this paragraph to match
  the state at the tag.**
- `stw tidy apply PLAN-ID` accepts an answer of `y` followed by end of input without a newline (issue #326, open;
  an existing behavior, not introduced by this release).
- Tracking references and merged-pull-request evidence need `gh` to be authenticated and a github.com remote;
  otherwise the wizard judges offline and says so.
- Git is the only backend for `stw sync`. Windows, the BSDs and illumos are not shipped.
- The release process itself is still the bootstrap tag workflow; the Spec 026 release machinery, the release
  wizard (Spec 045), `stw land` (Spec 043) and the stack toolbelt (Specs 012 to 016: specifications and a
  measurement record only) are not part of this release. Spec 029 gates (T044, T046 to T049) are not done.
- A dogfood dry run of the janitor on a copy of the maintainer's workspace (Spec 044 T016) and a scoped real
  apply on the live workspace (issue #70) were still open on 2026-10-27; see the
  [readiness checklist](../release-readiness-v0.2.0.md). Extend this list with their outcome.
- `whr` (WorkHarbor) is a separate project with its own release.

## Verify your download

Use the commands in the release body: `sha256sum --check --ignore-missing SHA256SUMS` (Linux) or `shasum -a 256
--check` on one archive (macOS), then `gh attestation verify ARCHIVE --repo wstein/sourcesteward`, then
`stw version`, which prints `SourceSteward v0.2.0`.
