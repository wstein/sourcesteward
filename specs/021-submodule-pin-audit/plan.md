# Implementation Plan: Submodule pin audit

**Branch**: `codex/021-submodule-pin-audit` | **Date**: 2026-10-16 | **Spec**: [spec.md](spec.md)

## Summary

Add `stw pins`, a read-only audit of a Git superproject's submodule pins. One bounded operation in `internal/inspection` reuses the existing ownership detection, reads registration from the HEAD blob of `.gitmodules` plus the gitlinks of HEAD and the index, validates each submodule's worktree and Git directory, gathers checkout, dirty and publication evidence through an isolated streaming Git runner, derives stable findings, and returns one typed result that the CLI renders as text or as versioned JSON. jj and ambiguous cases refuse with an explicit capability statement before any process starts, and the GitButler, bare and not-a-repository cases refuse after the existing Git detection.

## Technical Context

**Language/Version**: Go 1.27.2; Git 2.46 or newer (the existing minimum and current lanes).  
**Primary Dependencies**: Existing Cobra v1.10.2, the standard library and the existing JSON Schema test dependency. No new dependency.  
**Storage**: None. No plan files, recovery records or cache.  
**Testing**: Go table tests with real temporary Git repositories, schema fixtures, `scripts/smoke-pins.py` with its unit test, effect sentinels, existing architecture and documentation checks.  
**Target Platform**: Code supports linux amd64/arm64 and darwin arm64. CI evidence exists for ubuntu-24.04 amd64 only; arm64 and darwin results are recorded as local evidence.  
**Project Type**: CLI with a shared operation layer.  
**Performance Goals**: 5 seconds per submodule, 30 seconds total, 1 MiB retained output, at most 256 submodules.  
**Constraints**: No network, fetch, prompt, pager, hook, filter, helper, alias or write; submodule metadata is untrusted; nested submodules are not traversed.  
**Scale/Scope**: One superproject worktree and its direct submodules.

## Constitution Check

Pre-research assessment: PASS. Post-design assessment (after analysis findings were resolved): PASS.

- **I. Shared contract**: one typed result renders text and JSON; non-interactive; exit statuses 0, 1, 2 and the documented `--strict` status 3 with a stated precedence.
- **II. Evidence before actions**: read-only; the result states what it observed and could not, and that remote-tracking refs may be stale. It authorizes nothing.
- **III. Ownership and recovery**: no mutation and so no recovery claim. Ownership is verified first, with jj and ambiguity decided without a process. The audit checks submodule ownership itself because an explicit Git directory bypasses Git's `safe.directory` check.
- **IV. Specify and verify**: failing tests first; independent analysis before code; real temporary repositories; hostile fixtures, unusual names, concurrent change, interruption and limits; effect sentinels including a network sentinel and, on the refusal path, jj working-copy and operation-log sentinels.
- **V. Tier 1 peers**: Git is supported and conformance-tested. jj and GitButler are explicitly unsupported for submodules; the refusal is tested on the jj lanes and recorded in the backend contract. No equivalence is claimed.
- **Scope**: network is not used, and the result says so. Pin updates, fetch, push, hosting comparison and CI lanes for more platforms are separate specifications. No amendment or exception is required.

## Design Decisions

1. **Registry from three sources.** HEAD tree gitlinks and index entries (mode 160000) give pins; the HEAD blob of `.gitmodules` (read with includes disabled) gives names, URLs and tracking branches; the staged blob and the worktree file are compared and differences become `gitmodules-modified`. A path present in one source and not another produces a finding, not a refusal. A worktree symlink is never followed. A path registered only in the staged blob is not an orphan gitlink, and a staged-only registration without any gitlink is dropped from the registry and does not count toward the 256 cap. An unborn HEAD is confirmed (`symbolic-ref -q HEAD` resolves and `for-each-ref` finds neither the ref nor a broken one); any other `rev-parse --verify` failure is `pins-failed`. With an unborn HEAD a staged `.gitmodules` that is a gitlink, symlink or in conflict makes registration unknown. `url.configured` is the `.gitmodules` value; the superproject-local `submodule.<name>.url` is not reported.
2. **Validated worktree and Git directory.** The plan does not assume a shared `modules/` directory. Git keeps `modules` per worktree: in a main worktree it is `<git-dir>/modules`, in a linked worktree `<git-dir>/worktrees/<id>/modules`, and this was measured (`rev-parse --git-path modules` returned different paths, and the submodule pointer read `gitdir: ../../super/.git/worktrees/wt/modules/member`). The operation obtains the expected location from `rev-parse --path-format=absolute --git-path modules` for the worktree in use (without that option a main worktree returns a relative `.git/modules`) and accepts only a Git directory equal to that path joined with the submodule's Git directory name, or an in-place `.git` directory inside the submodule. Git 2.56 adds `extensions.submodulePathConfig` and `submodule.<name>.gitdir`; the round-2 review measured `gitdir: ../../.git/modules/a%2fb` for a name containing a slash, so the name is not always the submodule name. When the extension is set, the configured gitdir is accepted only if it stays confined under the modules path, and otherwise the submodule is refused with its own reason. The minimum lane (2.46) does not have the extension and the current lane covers it with a fixture. It reads the `.git` pointer as data. The allowed trees are the worktree's modules directory, and `<work>/.git` for an in-place directory. It then refuses a submodule whose Git directory has any `commondir` entry (a submodule never has one), whose `objects/info/alternates` entry leaves the allowed tree, is reached through a symlink, is not a directory owned by the effective user or carries alternates of its own, whose `config` or `config.worktree` contains an `include`/`includeIf` key or a `core.worktree` that differs from the validated worktree, or in which HEAD, config, config.worktree, index, packed-refs, shallow, the refs and info trees, objects/pack or objects/info is a symlink, FIFO or other special file (checked before any Git process and again before the first call). A worktree or Git directory that is world-writable, or group-writable by a group other than the effective group, is refused with `submodule-unsafe-owner`. Every invocation has a 5 second deadline and every transport is switched off by name (`protocol.<ext|file|ssh|git|http|https>.allow=never`, because `protocol.allow` is only a default) and `GIT_ALLOW_PROTOCOL=` (empty) forbids all others (ftp, ftps, fd, `<helper>::`). Alternates targets are walked like the object store (info and pack recursively, fan-out directories as plain files, reftable and `sharedindex.*` checked) and may not be the modules directory itself; exhausting the 20,000-entry walk budget is a limit (`pins-limit`), not an unsafe path. With `extensions.submodulePathConfig` a relative configured gitdir resolves against the superproject worktree root, as Git does; in a linked worktree Git 2.56 itself fails to create the submodule, and a configured value leaving that worktree's modules directory is refused with the distinct "not confined" message. Git always runs with explicit `--git-dir` and `--work-tree`. Directory identity (device and inode) is recorded and compared again before success.
3. **Ownership checked by the audit.** An explicit `--git-dir` makes Git skip its own `safe.directory` check, so `pins_safe.go` compares the owner of each submodule worktree and Git directory with the effective user before any Git process runs there and refuses with `submodule-unsafe-owner`. The check is Unix-only, matching the supported platforms.
4. **Publication through containment.** The operation first checks `cat-file -e <pin>^{commit}`, because `for-each-ref --contains` exits 129 for an absent object or a non-commit and failure could not be told from absence; an absent object gives publication `unknown` and, in an initialized submodule, `pin-object-absent`. Then one bounded call per pin, `for-each-ref --contains <pin> --count=64 --format='%(refname)%09%(symref)' refs/remotes/`, filters symbolic refs such as a remote's `HEAD` in Go, names at most 16 refs and flags truncation. `--count` applies after sorting, so the larger count only leaves room for the filtered symrefs. Local branches and tags are never consulted. The advisory freshness value is the modification time of `FETCH_HEAD` in the submodule Git directory when it can be read.
5. **Dirty state from metadata, never from content.** `git status` can run clean and process filters on stat-dirty entries, and the inventory comparison (`workspaceStatus`) turned out to be a poor fit: it fails above 1,024 index records, overflows the 64 KiB runner on `ls-files --stage`, reads every tracked file twice and reports `unknown` for any file over 64 KiB, any `text` or `eol` attribute, `core.autocrlf` or filter, so most real submodules would be `unknown`. Pins therefore decides tracked state from the index and file metadata only: `diff-index --cached` (index against the HEAD tree, no content comparison) for staged differences, and the index's recorded size, mode and modification time from `ls-files --stage --debug -z`, streamed and compared to `lstat` in Go. The comparison rules are fixed: sizes are compared modulo 2^32; the executable bit is ignored when `core.fileMode=false` and symlink mode when `core.symlinks=false`; a staged difference, a different size or mode, or a missing file is `present`; identical size, mode, modification time, change time and inode is `absent`; a difference in only the modification time, change time or inode, a racily clean entry (entry modification time not older than the index file's, in nanoseconds), an entry with skip-worktree, assume-unchanged, intent-to-add or a non-zero stage flag, a gitlink entry, a size-0 smudged entry, an unborn submodule HEAD in `diff-index` or a metadata block that does not parse is `unknown` with the reason. Git documents the `--debug` output as free to change, so the parser is fail-safe (an unparseable block means `unknown`, never a guess) and a format-pinning test runs on both Git lanes. Untracked presence uses a bounded `ls-files --others --exclude-standard`. Tracked and untracked scans share a budget of 3 seconds and 20,000 index entries per submodule; exceeding it yields `unknown`, never `pins-limit`. The work needs no refactor of the inventory code. Filter sentinels and an index-bytes-and-mtime sentinel cover it.
6. **Streaming runner and caps.** The shared runner caps each stream at 64 KiB, which is too small for `ls-files --stage` on a large superproject. `pins_run.go` consumes output incrementally, keeps only the records it needs (gitlink entries, `.gitmodules` keys), bounds retained bytes to the 1 MiB budget and the scan to a stated allowance, and reports `pins-limit` instead of truncating. Counts use two `rev-list --count --max-count=10001` calls (one per side), so each side is capped separately.
7. **Detection reuses the existing path, minimally.** `detection.go` already finds `.jj` by walking ancestors without a process, so a jj-owned or ambiguous workspace refuses with no process at all. GitButler detection, bare and not-a-repository come from the existing Git detection (`rev-parse`, `for-each-ref refs/gitbutler/`), which starts only Git processes, never jj and never a submodule command. The plan adds no new ownership logic, only the order: the process-free jj and ambiguity decision first, then the existing Git detection.
8. **Resample.** Superproject HEAD, index identity (size, modification time and object hash of the index file, read without refreshing) and each submodule HEAD are read again before success; a difference yields `pins-state-changed`.
9. **Findings are derived, not stored.** A single table in the spec maps evidence to stable codes and severities; the schema pins the code list.
10. **Exit statuses.** `internal/cli/root.go` has only `runtimeFailure` (status 1) and a fallback of 2 today. The plan adds one typed error for strict findings, checked before the fallback, that exits 3 and writes one line on standard error with the error-finding count. Precedence: usage 2, then refusal, operational failure, cancellation or incomplete result 1, then strict findings 3, then 0.
11. **In-place `.git` directories** inside a submodule are supported (old-style), validated by the same containment and ownership rules.

## Risks

- Git read paths can update the index opportunistically; sentinels on index bytes and modification time guard this, and every invocation runs with optional locks disabled.
- Metadata-based dirty state reports `unknown` for mtime-only differences and racily clean entries; the specification accepts that rate instead of running filters.
- The status names `incomplete` and `refused` and the code `pins-failed` differ from inventory's `partial`, inspect's `unsupported` and `git-inventory-failed`; they are consistent inside this contract and the choice is recorded in the research note.
- `FETCH_HEAD` freshness is advisory and may be absent; the schema models it as nullable.
- Non-UTF-8 paths cannot be represented in JSON; the entry is refused with `submodule-path-unsafe` rather than encoded.
