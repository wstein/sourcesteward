# Inventory CLI and adapter contract

## Invocation

`stw inventory [PATH] [--json]` is a new command. Existing inspect/version results and exits remain unchanged.
Flags: `--query clean|dirty|ref-exists|ancestor`, `--ref NAME`, `--from REV`, `--to REV`, `--base REV`, `--revision REV`, repeatable `--remote NAME`, repeatable `--scope tracked|staged|disk|stored|untracked|ignored`, repeatable `--path LITERAL`, `--anchor workspace|cwd` (workspace default).
Without query collect inventory; with query still return inventory envelope plus one predicate.
ref-exists requires only --ref; ancestor requires --from and --to; unrelated predicate operands are syntax errors. Clean/dirty accept file scope/filter options. Default scopes disk,tracked,untracked. `stored` means native stored revision delta; jj staging is unsupported, never fabricated. --base selects integration comparison; --revision selects containment; neither is required for unrelated queries. Remotes are explicit sampled remote-name selectors, never fetched. Literal path filters are anchored to selected workspace root or caller current directory, never expanded as shell/glob/revset/pathspec. Reject paths escaping workspace. Revision/name selectors must be validated/escaped for backend native literal interfaces, never concatenate user expressions into jj revsets.

## Common result model (inventory schema v1)

Root fields: schema_version=1, command="inventory", status=ok|partial|error, backend, input_path, identity (existing inspection Result), boundary, workspaces[], references[], bases[], files[], query (nullable), diagnostics[]. Empty arrays are arrays, not null.
Boundary: complete(bool), freshness="sampled-nontransactional", limitations (list of strings), limits (deadline_seconds=10, command_bytes=65536, result_bytes=1048576, records=1024).
Observation: value=true|false|unknown, reason(string). Known false remains a successful observation. Unknown unsupported/unreadable/incomplete carries a reason.
Workspace: path(string or null if native registration lacks it), name(string), manager(string), registration=present|missing|unknown, task_owner="unknown", commit_id(nullable), change_id(nullable), operation_id(nullable), tracked(Observation), untracked(Observation), conflicts(Observation), limitations (list of strings).
Reference: name, kind=local|remote|tag, remote(nullable), commit_id(nullable), change_id(nullable), upstream(nullable), upstreams (list of strings), added_targets (list of NativeTarget), removed_targets (list of NativeTarget), tracked(Observation), contains_revision(Observation), merged_into_base(Observation), local_only(Observation), limitations (list of strings). Local-only means not reachable from explicitly selected sampled remote references; absent selection/coverage gives unknown and never proves never-published.
NativeTarget: commit_id(string), change_id(nullable). Preserve all native conflicted bookmark targets rather than selecting one; absent unique commit_id/change_id stays null. Nested targets count toward the 1,024 aggregate record bound. Git nonconflicted references have one added target and no removed targets; native tracking eligibility remains backend-specific.
Base: name, commit_id(nullable), change_id(nullable), provenance(string), selected(bool), limitations (list of strings). Without explicit selection more than one candidate is ambiguous; no candidate guessed from conventional names. Configured/default native candidates must be identified safely, without evaluating alias/helper text. Expression-valued config that cannot be resolved safely remains qualified unknown.
File: path, old_path(nullable), scope enum, change=added|modified|deleted|renamed|copied|untracked|ignored|conflict|unknown, limitations (list of strings). Preserve names exactly (JSON encoding); reject undecodable machine records rather than replace bytes silently. Unsupported selected scopes are disclosed in boundary/diagnostics, not silently omitted.
Query: predicate, value=true|false|unknown, reason, evidence (list of strings). Clean/dirty only known if every requested relevant scope is complete; dirty false is not inferred from unavailable evidence. Native full identities appear in evidence; ambiguous revisions produce unknown/refusal, never arbitrary selection.
Diagnostics reuse code/message fields. Unknown observations not necessary for requested scope (e.g. task_owner) do not themselves force partial. Required unavailable evidence does: status=partial, boundary.complete=false. Cancellation, timeout, malformed native output, missing backend, unsafe ownership and limit exceedance yield error/complete=false; retain only explicitly qualified observations, never silently truncate and claim complete. Existing error renderer emits one structured result and operational exit1. Known false exits0, partial/unknown exits1, syntax exits2. No boolean exit-code overloading.

> Amended for the Git adapter by [Spec 027](../../027-inventory-limits/contracts/inventory-limits.md): streamed reads, limits, degradation, checkout description and gitlink rules. The 64 KiB native-output and 1,024-record statements below describe the original contract; Spec 027 states what they mean now.

## Go boundary

`Inventory(ctx context.Context, path string, options InventoryOptions) InventoryResult` lives in internal/inspection.
InventoryOptions carries Query, Ref, From, To, Base, Revision strings; Remotes, Scopes, Paths []string; Anchor string.
`inventoryGit(ctx context.Context, identity Result, options InventoryOptions) InventoryResult` and `inventoryJJ(ctx context.Context, identity Result, options InventoryOptions) InventoryResult` fill the common model. Root orchestration detects ownership with Inspect, applies one total ten-second context, validates options, initializes envelope and enforces aggregate limits. Native adapters reuse safe runners; jj session setup becomes a reusable internal callback/session operation with the same cleanup, isolation, version/probe and operation-pinning enforcement as inspectJJ. No new public inspection result fields are required.

## Effects and native qualifications

No target writes, snapshots, refresh/prune/fetch, hooks, editors, prompts, shell helpers or network. Private jj isolation/probe files outside target remain the disclosed temporary effect. jj workspace metadata and diffs are stored unsnapshotted: disk tracked/untracked/conflict freshness is unknown unless independently safely observed. Do not read jj state through raw Git. Missing workspace paths are reported without repair. Foreign ownership of a registered workspace is reported without backend fallback or querying that foreign workspace.
Git inventory disables optional locks/fsmonitor/untracked cache and lazy fetch; fixed object/index plumbing must not invoke textconv, external diff, filters or configuration-controlled helpers. Disk comparison uses confined raw blob reads (64 KiB per file), never Git status/worktree diff hashing. Larger files, configured normalization and excluded native disk capabilities remain qualified unknown. Git directory/file names use NUL-safe interfaces; jj uses escaped JSON templates and native literals. Compare relevant registration/revision/operation samples before/after; report changed evidence and disclose ABA/races not detectable by sampling.

## Scope and predicate precision

For Git, staged compares index against HEAD (unborn HEAD uses empty tree); disk compares tracked worktree files against index; tracked is the union of staged and disk tracked paths, preserving both scope records if requested separately. Untracked excludes ignored entries; ignored includes only explicitly requested ignored entries. Neither scope recursively scans arbitrary neighboring directories. Stored compares selected --revision (default observed checkout) against --base when supplied, otherwise its sole parent; root revisions compare against empty tree. A multi-parent stored revision without --base has unknown stored comparison and requires explicit selection, rather than silently selecting first parent. Bare state has no disk/index observation. Rename/copy classification is reported only from a native bounded result with documented heuristic settings; when rename inference is disabled report independent deletion/addition, never invent a rename. Retain old_path for native rename/copy records.
For jj, stored compares selected revision against explicit --base, otherwise against native merged-parent tree as documented by jj diff -r; this is a backend-specific merged-parent comparison, not Git first-parent equivalence. Stored conflict facts are not disk conflict freshness. Disk/tracked/untracked/ignored observations unavailable without snapshot are unknown; staging is unsupported. File exclusions and requested scopes always appear in boundary limitations when absent.

With --query ref-exists or ancestor, omit file-state collection entirely; the default disk/tracked/untracked scopes apply only to ordinary inventory and clean/dirty queries. Reference predicates skip unrelated workspace/file/base-candidate collections; --scope with a reference predicate is a syntax error. Query completeness depends only on that predicate's operands, not unrelated optional facts. A successful absent-reference or false ancestry result with no requested additional scopes is status=ok and exit0 on both backends. Operational failure takes precedence over a known predicate result. Unrequested task ownership, missing upstream, absent integration operands and native disk limitations cannot independently force query failure. Ordinary inventory exposes those limits, but only unavailable requested observations force partial.

Git upstream retains its canonical single relationship; upstreams preserves all native jj tracked-remote relationships, without collapsing them to one upstream. Literal filtering retains a rename/copy if either old or new path matches; source path becomes old_path only for actual rename/copy records.
