Decisions and findings of this package (no requirement or contract was changed):

- Contract amended by the foreman: measured on Git 2.56.0, `git patch-id` prints a patch-id of the width of the object format (64 hex digits in a SHA-256 repository). The patch-id grammar follows the object format and the byte bound is 537,600 bytes for SHA-1 (5,120 x 105) and 665,600 bytes for SHA-256 (5,120 x 130); code and bounds tests use these numbers.
- `diff-tree --stdin --numstat` and `--name-only` run with `--no-commit-id`; without it Git prints the commit id before the records and the contract grammar has none.
- No merge base counts like several: `ambiguous-merge-base` (FR-003 needs exactly one).
- Review follow-up tests: `TestPatchIDWithoutAMergeBaseIsAmbiguous` (unrelated histories), `TestPatchIDReportsWhitespaceWhenOtherwiseUnproven` (`whitespace-differs` next to `partial-match`), `TestMergeNoopMergeTreeFailsClosed` (exit 2, 128, 1 without a tree, extra stdout on exit 0, no or malformed tree: `proof-limit`), `TestApplyRetainsWhenTheReevaluatedVerdictDiffers` (the apply comparison is reached through the `proofRunner` seam for each evidence field), `TestPlanOnlineEvidenceUpgradesNeedsReviewAndHonoursUnselectedAncestor` (needs-review tips remain eligible for online evidence; an unselected ancestor class never proves).
- `merge-driver` is decided by the configuration in effect under the planning environment (the repository and its includes), not by the admission read that also shows system and global files: git-lfs installs `filter.lfs.*` system wide on CI runners, which blocked `merge-noop` there. Regression: `TestMergeNoopIgnoresHostConfigurationDrivers` (global and XDG host drivers and lfs filters ignored, the same driver in the repository still blocks) and the contracts scenario with a host `~/.gitconfig`; the contracts failure message now lists `git config --show-origin --list` as the admission read and the planning environment see it.
- A tip with no proof and no reason is still `integration-not-proven` (Spec 029), because the evidence record requires at least one reason for `needs-review`.
- Grafts, shallow metadata and alternates are hard stops only in a local-reference planning context; apply keeps the strict admission, so a repository with these files plans every proof-eligible ref as retained and apply refuses.
- A FIFO as `info/attributes` blocks Git itself when it reads attributes, so the planning observation fails closed at its 10 s limit instead of reporting `attribute-source`; the classification of a special file is unit tested without opening it.
- `ProofEvidence.refs` is not stored (candidates are per reference) and the V3 journal is unchanged: a journal binds the plan digest, which binds class, flags and counts.
- T013 stays partly done: the binary patch-id measurement is a test on the installed Git 2.56.0; Git 2.47.3 is not installed in this environment.
