# Plan: `stw issues` and its status integration (Spec 038)

Test-first throughout (a failing test before behaviour), fake forge, no network. Each work package is for one middle-tier author and
ends with its tests green and `make check` clean. Seams: a new `internal/issues` (stateless cycle and priority rules, pure over the
`watchcmd.Reader` interface, mirrors `internal/pulls`), `internal/hosting` (three shapes, guard mode `issues`, typed decoders,
`user`), `internal/watchcmd` (`esc`, `ValidRepo`, `Resolve`), CLI wiring like `internal/cli/pulls.go`. Order: **WP-0**, then WP-A and
WP-B in parallel (disjoint after WP-0), then WP-C, then WP-D (which needs Spec 037's WP-0 and WP-D action model merged or as base).

## Test plan and mutation targets

In-process HTTP injection seam (Spec 022 FR-009), no network. A mutation target is a one-line change a test must kill.

| Area | Tests | Mutation targets |
| --- | --- | --- |
| Guard (0, B) | matrix of the five modes against the three shapes and the PR search: `issues` admits list, `user`, issue search, refuses PR search and the watch set; `status` admits list and `user`, refuses both searches; `pulls`, `watch`, `one-shot` refuse all three; list shape refuses `per_page=99`, `state=all`, `labels=`, `page=0` and `11`, extra parameter, other order, lowercase escape, encoded `%2F`, POST, redirect, other host; `user` refuses a query string and `users/x` | admit the PR search in `guardIssues`; admit search in `guardStatus`; widen the list regex to `state=all`; let `guardWatch` admit `user`; drop the method check |
| Decoders (0) | entries with `pull_request` dropped (also `null` value); label objects, missing `name`, non-string; `user` null (ghost); `number` 0, string, huge; 101 entries; 1 MiB plus; 410; `Link` to another host never followed; `login` invalid in `user` | keep PR entries; follow the `Link` URL; accept a 101st entry; treat 410 as an error |
| Priority (A) | one fixture per rule; precedence: `security` beats bot, assigned and bug; assigned beats bot and bug; bot beats `bug`; case (`SECURITY`, `Bug`); exact only (`security-review`, `area/security`, `security ` with space, `security` plus zero-width space are not red); `security` as 100th label is red though the row keeps 20; viewer unknown disables only rule 2; assignee case-insensitive; reason recorded | swap rules 2 and 3; substring match; case-sensitive match; compute the rule after the 20-label cut; treat unknown viewer as match; make `bug` red |
| Viewer (A) | `ok`; 403 is `skipped`/`viewer-unavailable`, exit 0; 401, 500, network, malformed are `error`, exit 1; one read per run (counted); `--assignee @me` with no login exits 1 and prints no rows | retry the read; count 403 as failure; print rows with unresolved `@me` |
| Filters and cap (A) | labels any-of, flags intersect, `@none`, `@me`, authors with `[bot]`; filters never reach the URL (recorded requests carry no filter); cap keeps red first, `omitted` and `counts` correct; sort invariant under shuffled repositories and goroutine timing | send the filter as a query parameter; cap before sorting; counts after the cap |
| Partial failure (A) | repository 500 on page 2 discards its rows and lists the error; `too-many-open-issues` keeps the oldest 1000 marked partial; rate limit mid-run stops all requests and never sleeps (clock injected, never advanced), exit 1; 410 `issues-disabled` is no error | keep rows of a failed repository; sleep or retry after a rate limit; continue after a rate limit |
| Owner (B) | as the pulls owner tests with `is%3Aissue`: user, organisation, empty, `incomplete_results` precedence over `total_count` 0, `search-too-many` above 1000, 10-page bound, foreign `repository_url` ignored, repeated owners throttled; search used only for names | follow the 11th page; trust `total_count` over `incomplete_results`; read issue data from the search |
| Output and security (C) | human and JSON goldens, `esc` of titles, labels, logins (ANSI, CR, NUL, bidi, 10 kB), 120-character bound, JSON 2048-byte cut on a UTF-8 boundary, `https` URLs only, `command` only from validated tokens, token canary never in stdout, stderr, JSON, errors, hints; no colour on a pipe | skip `esc` for a label; build `command` from a title; print the token in an error |
| Schema (C, D) | valid and broken fixtures per new key, `additionalProperties` false, freeze digest, `UNPUBLISHED_SCHEMAS` test, `command`/`effect` pairing, `labels_total` against `labels`; status additions: enum, `sources`, `remote.sources.issues`, v1 digests unchanged | stale digest; extra keys allowed; `effect` set with null command |
| Status (D) | `issues: N open (R red, Y yellow)` line; red and yellow become items, blue and violet never; grouping into one line with 3 ids and `+N more`; failed read gives one `read-error` and no issue item; deadline skip is no item and exit 0; issues source independent of the others; count parity with `stw issues`; no search in status (guard refuses it); request count is pages plus one `user` | emit an item for a blue issue; both an item and a `read-error`; send search from status; let a deadline skip raise the exit status |
| Concurrency | at most 4 repositories in flight, sequential within a repository | unbounded fan-out |

Authors run `go test -race` once per package before the first push; reviewers run the affected tests and their own mutation probes.

## Risks

See the spec. No build, release, tag or publication is part of any WP; a `stw` build for dogfooding needs the owner's approval.
