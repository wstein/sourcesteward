# Tasks: Stack inspection and plan (v2)

**Input**: `spec.md`, `plan.md`, `research.md`, `data-model.md`, `contracts/stack.md`, `contracts/later-effects.md`, `analysis.md`.
**Tests**: Required by constitution principle IV. Write each behavior test and observe it fail before the implementation; characterization and byte-equality guards (T007 and the unchanged-bytes assertions of T003) cannot fail first by construction and are committed green before the code they guard. Task checkboxes record execution, not design approval.
**Work items**: Tasks are grouped into six work items, WI1 to WI6. Each is one reviewable change that builds on the previous one and ends with `make check` green; WI order is the stacking order of the pull requests. No work item exposes the command on one backend only: the `stack` command is registered in WI4, after both adapters. Each task names the requirements (FR) and stories (US) it covers; success criteria (SC) are named where a task is their evidence. A source-only run never counts as acceptance for a lane it did not execute.
**Authorization**: Source tests, vet and formatting run automatically. No artifact, image, release or site build runs without the owner's explicit approval (AGENTS.md); neither does any live write to GitHub. T023 needs the owner to create an open native stack if none exists.
