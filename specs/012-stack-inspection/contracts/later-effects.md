# Catalog: later stack effects (not part of this feature)

**Refreshed 2026-10-25; proposals only.** Nothing in this catalog is implemented, authorized or accepted by Spec 012. The historical 2026-10-17 catalog and native-stack spike motivated separate optional effects; it is not permission to execute them. The separate hidden Spec 015 Git `restack plan` v1 exists in source; local apply, jj and forge effects remain proposed and require their own acceptance. No JSON contract is published by this Markdown catalog.

## Common rules

1. Default selection is **none**. Every local mutation or forge effect needs its own inspectable plan, exact targets, expected state, limits, recovery record and explicit action authorization plus that effect owner's plan id. No plan alone grants authority, and no observation or local mutation implicitly selects a remote action.
2. A Spec 012 observation is optional evidence, not proof or an apply receipt. The existing Spec 035 restack-needed watch event is separate from the proposed 012 restack-advised finding and is not that observation or a 015 plan: never coerce its payload, substitute its merge-commit destination implicitly or execute its event argv as an effect plan. Each consumer rereads relevant native/remote state and refuses stale or incomplete evidence. Spec 015 first-slice D6 selects explicit old parent/new parent/branch without a hard dependency on 012.
3. Native stack semantics remain GitHub's. No local rewrite competes with GitHub's native rewrite; the observation reports the measured versus unknown state and never silently takes a remote head, discards local work or initializes a stack.
4. Forge effects belong to Spec 016, through separately reviewed native Git/jj publication or bounded transport capabilities. The current Spec 022 GET-only transport is not write authorization. No unreviewed shell command, extension subprocess, response URL or repository text supplies a write endpoint or permission.
5. Every selected effect records intent before execution, per-action outcome, uncertain/partial completion and retry reconciliation. Local undo cannot reverse a remote publication. Spec 013 owns explicit local checkpoint/restore/selective undo using Spec 032 durability conventions; this catalog adds no second journal implementation.
6. Ownership, Spec 041 mode rules and Spec 042 task attribution remain independent gates. Name matches, commit identity from config, a previous agent's authorization or an environment-derived expected identity never substitute for ownership or explicit `--identity` evidence. No session id appears in public artifacts.
7. After actual Spec 015 local apply, Spec 016 may render a blocked plan; before push it independently applies the [actual-head/change-class policy](../data-model.md#optional-downstream-evidence-handoff). Specification/documentation-only rewrites need green documented checks and diff checking, plus equal range-diff for a pure rebase; code/test/script/generated rewrites need exact-new-SHA independent pre-push review, with middle-tier review allowed for an equal pure rebase. Ready always requires independent exact-head CLEAR, required green CI and rebaseability. A predicted fixed-committer quarantine SHA and an old review never substitute for the applicable actual-head evidence. The fresh remote lease names its exact full expected SHA; never plain force or a bare lease.
8. Git and jj retain native mechanisms and explicit gaps. No raw Git write substitutes inside a jj-managed workspace. No default-branch push, merge, tag, release, settings change, foreign-owned action or owner-checkout resync is selected by this catalog. Spec 043 landing is a separate human-only invocation.

## Items

The labels are historical workflow names, not newly registered commands. All are unscheduled in Spec 012.

| Id | Effect | Owner | Mechanism and current boundary |
| --- | --- | --- | --- |
| L1 `stack link` | Link explicitly selected existing owned PRs into a native stack or extend one | Spec 016 | The historical `gh stack link` v0.2.1 help (M6) described branch pushes/missing-PR creation; numeric linking's push behavior was unmeasured. Do not inherit those side effects. Any PR creation or push is separately selected and authorized. Stack REST write endpoints require measurement and a reviewed closed transport amendment; ambiguous PRs, split stacks and fork heads refuse. |
| L2 `stack push` | Publish only named owned topic refs, in explicit order | Spec 016, separate from Spec 015 D8 | Normal fast-forward push and a separately selected lease rewrite are distinct actions. A lease rewrite requires a full expected remote SHA read freshly, explicit ref/full new SHA and actual-head checks/review according to the change-class policy in common rule 7; recompute evidence including merge commits. `Layer.upstream.commit_id` is sampled cache, never the final lease. Historical Spec 016 FR-006 forbids force-push in its original slice; only its explicit reviewed lease amendment can enable L2. Hooks/network are disclosed by that effect owner. |
| L3 `stack sync` | Compose separately selected observation, fetch, local restack, publication and link | Specs 015 and 016 | No omnibus authorization or implicit step. A native stack is observed rather than locally rewritten. Spec 032 `stw sync` has a separate explicit fetching contract and is never invoked automatically here. |
| L4 `stack unstack` | Dissolve a selected native stack while retaining its PRs | Spec 016, deferred | Endpoint and partial behavior remain unmeasured. Historical help said queued/auto-merge PRs may remain stacked; report actual per-PR outcomes, never infer success. |
| L5 `stack merge` | Historical proposed native-stack merge | Deferred owner decision, outside agent Spec 016 apply | Historical M6 help described all-or-nothing stack merging; the spike did not measure it. No agent merge path is authorized. Human-only single-PR fast-forward landing, child retarget and optional own-head deletion belong to Spec 043 and its separate gates; this catalog neither invokes nor amends them. |
| L6 local restack | Replay selected local layers with retained recovery evidence | Spec 015 | Preserve D7: quarantine/plumbing replay and compare-and-swap, not porcelain rebase. The printed 012 `git -c rebase.updateRefs=false -c rerere.enabled=false rebase --onto`/`jj rebase -s` forms describe human replay semantics only; never execute them as a trusted apply plan. Later jj support requires its own native capability/conformance evidence. |

`stack plan` prints `fetch`, `rebase`, `link` and `observe` text only. Native read adapters may start their allowlisted read processes, but no printed effect command is started. A later consumer creates and revalidates its own plan; every action remains separately selected. No local apply or owner resync is performed by observing this catalog.
