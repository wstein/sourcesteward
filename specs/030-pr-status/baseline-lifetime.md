# Replacement lifetime design against accepted hosting behavior

**Status**: Concrete replacement proposed by the same author for a separate technical/risk assessment, **not formal round4**. Three previous DESIGN NOT CLEAR results remain counted; round4 is unspent. Runtime is unauthorized until complete formal DESIGN CLEAR and file handoff. This replaces the current recommendations in auth-lifetime.md and round3-disposition.md; their failed stronger certificate is retained only as review history.

## Required behavior versus withdrawn certificate

Preserve accepted [hosting behavior](../../docs/hosting.md): caller authentication and jj read-only operation pinning at lines34–41; total30s/capture/body/native limits at48–56. [Spec022 transport](../022-bounded-go-gh/contracts/transport.md) requires inherited authentication cancellation at7 and body closure/overall deadline at15. Native execution uses CommandContext/Run with1s WaitDelay (`inspection/git.go:47–58`, `inspection/jj.go:306–326`, `hosting/transport.go:195–215`); private jj setup must clean up before returning (`jj.go:82–85,115`). None of those sources promises an exhaustive independent certificate for every descendant when OS process queries fail. Current implementation limitations do not authorize raising the accepted30s bound.

Withdraw the author-proposed requirement to enumerate and certify every descendant's nonexecution before output, including after query failure or leader death. Do not replace it with a false equivalence: a successful direct Wait, stream closure, empty child list or group signal still does **not** certify transitive descendant termination. The replacement makes no such claim and performs no process-tree queries, group discovery, STOP/CONT coordination, added process-group signalling, subreaping or persistent supervision. It retains full existing authentication, supported Linux/macOS native ownership, every sandbox flag and the five requested features.

The host requires completion of **its actual direct subprocess calls, Go capture-copy tasks, owned HTTP operations, private cleanup helper and descriptor closures** before guarded final output. Call this `owned-calls-completed`, never `all-descendants-stopped` or an unqualified resource-free certificate. A prepared delivery is immutable output data plus candidate exit code, not a closure retaining operation callbacks/cleanup. Existing external services and potentially surviving inherited descendants are not falsely certified by that value.

## One absolute budget and admission rule

Record D=min(start+30s,parent deadline) before native/auth work; W=max(start,D−3s), T=max(start,D−1s). Ordinary maximum allocation is27s operation,2s teardown and1s formatting/stdout/stderr. This is a disclosed engineering allocation inside30s, not30s polling plus a cleanup tail. No request/child starts at or after W, after parent cancellation, or with insufficient reserved teardown capacity. If less than3s remains at entry, return operational timeout before native/auth/network. Syntax/flag errors remain exit2 before effects. Native10s subcontexts remain tighter. Parent cancellation enters teardown immediately; it never renews W/T/D.

At work stop S, the teardown ceiling is min(T,S+2s). Fixed constituent caps are1s direct native/auth Run/Wait tail,250ms owned HTTP abort/close/join,500ms private deletion execution and200ms deletion-child kill/reap:1.95s conservatively; native/auth and HTTP are mutually exclusive. Cutoffs are absolute, checked before and after each synchronous step. Earlier serial jj setup/cleanup consumes the same W and cannot start another session after failure. This covers all five existing jj sessions, not solely the final hosting cleanup. At most one private root is outstanding because the next session is forbidden until prior deletion acknowledgement.

Timing retains the accepted responsive supported-OS/filesystem assumption: kill/wait/close and regular metadata syscalls must complete, and the process must be scheduled. No context interrupts an arbitrary kernel syscall, and WaitDelay does not bound an unkillable direct child. Do not sell hard realtime, arbitrary injected callbacks, failed-kernel or hostile native-executable behavior. This is the same boundary as the established native/HTTP API, explicitly disclosed; it is not permission for a new unbounded application closer, abandoned goroutine or asynchronous deletion queue. Fixed-production HTTP/helper conformance must meet the phase ceilings before implementation acceptance; a test that cannot meet them is failure, not permission to extend D.

## Owned HTTP and private cleanup

Use the fixed typed GET and existing destination/redaction guards. The watch-only standard transport owns its raw connections/dials: close the admission gate, cancel request/dial contexts, immediately deadline and close each owned raw TCP connection, then close the corresponding response body and join tracked I/O/dials. A late dial closes rather than publishing a connection. Apply abort-before-close to every error/body/compression/size rejection as well as successful reads. Only then CloseIdleConnections. No next GET until preceding body handling returns; no caller-owned shared transport/global mutation. The250ms completion allowance is checked against the original cutoffs. The fixed Go transport/unblock ordering and source-only net.Pipe evidence are detailed in [component protocols](watch-lifetime.md#owned-http-completion-protocol). Do not accept arbitrary non-abortable RoundTripper/ReadCloser fixtures as equivalent production capability.

Replace only enhanced-watch private root cleanup with the previously specified fixed **leaf cleanup helper**; legacy one-shot/CI behavior stays. Acquire the parent directory capability before creation, then register the exclusive0700 root fd/device/inode before copying metadata or starting a child. If registration fails after creation, start no native/auth child, close acquired descriptors and report private residue/incomplete; never guess a delete target or follow a fallback arbitrary path. Require the direct native/auth call and capture tasks to have returned before deletion, matching the existing sequencing. This does not assert all inherited descendants are gone. jj's read-only sandbox and neutral gh lookup request remain unchanged, including on cancellation; no writable target or broader credential access is introduced.

The helper receives only owned directory capabilities and expected leaf identity, through a private cmd-owned protocol, never arbitrary delete paths or a public command. Verify current UID/0700/device/inode; fd-relative O_NOFOLLOW traversal≤64 entries/depth8, no file-content reads, no descendants/network/auth, recheck identity before unlinking the root. A qualified trusted executable image performs the helper mode; no shell/PATH helper, install or new daemon. Its execution cutoff is min(now+500ms,teardown ceiling−200ms). Cleanup uses a fresh bounded context tied to those original absolute cutoffs, not the already-cancelled work context and not a renewed operation clock. Parent cancellation stops work but must not prevent the required bounded cleanup attempt from starting. No start without reap reserve; kill on cutoff, synchronously Wait/reap within200ms, close parent's capabilities. Acknowledgement is deletion success, typed failure, or no root created; never a detached deletion. The [existing finite deletion prototype](watch-lifetime.md#executed-finite-prototype-and-remaining-verification) demonstrates confinement, failed identity and killed/reaped residue cases, not complete platform acceptance.

On failure, stop sampling, exit1 and mark boundary.complete:false. A failed deletion may leave at most one0700 root with0600 copied private jj metadata; tokens stay memory-only. Never leak contents/raw errors/source paths, relax permissions, queue a retry or call failed deletion completed. Retain `private-metadata-residue-possible` in limitations and `hosting-teardown-failed` unless timeout/cancel already has primary diagnostic precedence. Private root deletion can succeed while an inherited descendant's OS state remains unknown; these are different claims. No PID/PGID/orphan status is invented. Bounded fd-relative deletion does not follow an inherited child's symlink or extend authority outside the private root.

## Final delivery, result meaning and disclosure

Command-host capability is checked before effects. Both existing executable entry points support ordinary inherited stdout/stderr, regular files and terminals through the command-owned final-delivery arbiter; a library without that host protocol refuses explicit watch before native/auth/network. After `owned-calls-completed`, final formatting, stdout and root stderr run synchronously under the original D/parent-cancel arbiter. It owns the sole command exit; no library os.Exit, blocked writer goroutine or monitor-disarm gap. Deadline/cancel wins over a submitted success code, then exit1. If D/cancel already holds at entry to delivery, start no output and exit1. This guard never bypasses a direct Wait, owned HTTP close/join, helper Wait or outstanding operation-level cleanup.

This replaces the old claim that delivery entry proves every external descendant stopped. It proves the enumerated **owned calls** completed. Abrupt owner death/SIGKILL, external trusted-service lifetime, transitive native descendants and failed-kernel scheduling are not independently certified. The final process exit does not purge their OS metadata. These limitations do not permit an abandoned SourceSteward writer/closer/helper goroutine, continuing GET loop, live direct child owned by an unreturned Run or deferred private deletion.

Every v2 watch result, including early error and output-limit fallback, includes the stable limitation `native-descendant-state-unverified`; the schema requires it. `boundary.complete:true` means the requested PR observation succeeded under its sample/expectation/budget rules and the listed owned calls returned successfully; it is **not** process-tree cleanup attestation. Diagnostics remain at most one and exits remain0/1/2. The static limitation is also documented in public watch help and explained in detailed output. Compact remains one line; no extra progress stream. No observation claims an actual orphan exists. A failed/truncated output can prevent receipt of any limitation, as with existing writer failures; consumers must require complete JSON and exit0.

## Technical/risk assessment requested before formal round4

The meaningful inherited risk is that direct-child cancellation/capture closure can return while a native/auth descendant is not independently known stopped; the source-only direct-parent-kill and early-leader-death cases establish exactly that distinction. It must not be relabelled as clean tree shutdown. The accepted cancellation primitive already has this limitation; watch uses it once, with an earlier cutoff and no repeated auth/native work. It does not gain a tree-supervision promise or new daemon. Existing full auth and sandbox security boundaries remain.

New watch-specific implementation surfaces requiring technical review are: bounded fd-confined private deletion with explicit residue instead of ignored RemoveAll errors; owned raw-connection abort/close ordering; phase accounting; and cmd-only final exit after enumerated owned completion. Private residue is already possible with ignored cleanup errors, now bounded/reported unsuccessful rather than silently assumed removed. The helper adds one owned leaf process and no new authority; its start/kill/Wait/protocol must be tested. No accepted total bound, endpoint/auth support, native target effect or platform capability is intentionally changed. Assess any contrary concrete accepted-contract conflict rather than presuming all proposal changes require owner approval.

The separate same-reviewer assessment must determine whether this baseline replacement/disclosure is technically honest and whether any material **new** risk needs disposition. It does not consume formal round4 or imply DESIGN CLEAR. Production terminal/Darwin, actual fixed transport/helper cancellation and both-entry integration remain implementation acceptance obligations after formal clearance, not a substitute for a designed mechanism. No further containment research or implementation is selected by this candidate.
