## High: why the current terminal transition cannot be completed as written

The candidate required independent complete nonexecution observation before delivery, including when observation fails. Its stopped-parent child list works only while that parent remains alive. The review's actual Linux counterexample keeps a dead leader unreaped while its child list is empty and an orphan still executes in the original group. Therefore neither identity pinning nor an empty list supplies the missing certificate after early leader death. No larger W/T/D reserve changes that fact.

A concrete finite whole-group scan could read `/proc` once, cap directory records, read each stat with bounded bytes and reject errors/overflow. That bounds application work, but the terminal outcome on query error, an unreadable unknown member or record-limit overflow remains **ownership unknown**. Treating that as empty, retrying without a bound, or calling it nonexecuting merely because a group Kill returned would violate this candidate. Killing the known leader and closing local capture descriptors supplies direct Wait/local-stream closure only; it cannot turn an unobserved orphan into an observed nonexecuting process. Continuing to scan until certification supplies no finite failure bound. The same problem applies to an incomplete Darwin group query. These are distinct observable states; a static error diagnostic cannot erase the distinction.

A registered Linux pidfd is an independent termination witness for its particular process, surviving parent loss and metadata-query failure. It does not register an undiscovered child retrospectively. A discovery/registration design must address the interval before publication/open and producer death during that interval, rather than infer that successful later registrations cover every child. Existing gh auth does not expose a child-registration handshake. Adding a group scan around it does not close the terminal transition above.

The truthful finite outcome with the present evidence is **candidate rejected; no resource-free final-delivery certificate** on those paths. That is a design result, not an allowed shipping watch result, a new runtime hang, an owner-approved leak or permission to arm final-delivery C over active workers. The counterexample does not assert that existing SourceSteward leaks workers.

## Opposing native model and exact limits

`/tmp/stw-spec030-round4-assessment/native_session_test.go` is an inert source-only Linux model, not a bubblewrap/jj execution. A monitor starts a worker with a new session and parent-death SIGKILL. The outer fixture registers that **known** worker using pidfd before triggering either outcome. Normal control waits/reaps the worker and writes an actual-Wait acknowledgement. Abnormal monitor death still causes the worker's registered pidfd to acknowledge termination, while no parent-Wait acknowledgement exists. Both cases pass; the worker's group differs from the outer monitor group. The fixed worker never forks or accesses credentials, repositories, mounts or network.

This provides a positive nonexecution witness across the actual session boundary and an opposing control distinguishing nonexecution from parent reaping. It deliberately gives the fixture a known registered PID: actual production's missing discovery/registration guarantee is **not** solved by the fixture. No orphan reaping is claimed for the abnormal case; no executing test worker remains. PIDfd observation is Linux-only, and no Darwin execution is claimed.
