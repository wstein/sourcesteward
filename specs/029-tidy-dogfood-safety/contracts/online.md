# Online evidence contract

Only `internal/hosting` performs HTTP/authentication. Expose a typed operation-scoped session to the v3 workspace coordinator: resolve selected repository identity, discover exact-head PR candidates, read selected merge evidence, and read a complete branch advertisement. No arbitrary route/command function is exposed to workspace or CLI. Existing `hosting.Inspect` and published hosting v1 schema remain unchanged.

## Budget and trust boundary

Initialize only after explicit online acknowledgment and native preflight. Reuse bounded caller-owned gh authentication, pinned go-gh transport, fixed github.com destination, safe API version/header policy, no redirects/compression/decompression/cache/logging/API-host/socket override, no credential setup or Git transport. Caller proxy policy stays the existing hosting contract. Bind provider base repository numeric ID and node ID plus normalized host/name; identity changes/redirects refuse.

One shared run budget:30-second online plan /60-second apply total, native subdeadlines retained;128 requests,32 MiB raw response bytes including errors/retries/rechecks,1 MiB each raw/normalized body/result,16 KiB each auth stdout/stderr. No automatic retry resets. Lists use100 rows/page, at most10 pages/1,000 unique records; validate Link destination/path/query/page progression if present, but generate only admitted next-page requests. Exhaustion requires an authoritative terminal page/link state consistent with row count; a full final page without proven exhaustion refuses. Duplicate/malformed rows, changed totals/pagination, unsupported encodings and missing fields refuse. Authentication preflight failure has network_attempted=false; any sent request makes it true even if observation fails.

## Repository and PR proof

Resolve the exact selected local remote URL through existing bounded native remote evidence. One unambiguous GitHub repository, no helper transport, conflicting URLs or URL rewrites. Optional `--repo` must agree. Read `GET /repos/OWNER/REPO` and bind its ID/node ID/full_name/default branch facts; re-read identity at final boundaries. The chosen local `--base` selector/OID is explicit and independent of the provider default branch or original PR base name. Full local commit/base identities and absence of graft/replace ambiguities remain native requirements.

Default discovery uses `GET /repos/OWNER/REPO/pulls?state=closed&per_page=100&page=N`, complete bounded pagination without head/base-name filters. Select rows by exact target OID, then fetch `GET /repos/OWNER/REPO/pulls/NUMBER` for every selected candidate. List data is a hint, never proof. Explicit OID=number hints replace discovery for those OIDs; unhinted OIDs still use complete discovery. Unknown hint OIDs or conflicting mappings refuse. No title/body/comment/patch/CI data is retained or used.

A complete admissible merge tuple is: host, repository ID/node ID/name, PR ID/node ID/number, closed state, merged=true, nonnull merged_at, nondraft state, head repository ID/node ID/name/ref/OID, base repository ID/node ID/name/ref/OID, nonnull full merge_commit_sha. Both repositories must equal the selected repository; fork/deleted-repository facts retain as unsupported. Every OID is full SHA-1 for this online capability. Require head OID=local target and native merge_commit_sha ancestor of the exact selected local base OID. Missing local objects refuse without fetch. Original PR base ref and SHA are bound and resampled, not required equal to the selected local base selector/OID. An intermediate stack branch may be deleted or renamed without invalidating unchanged PR facts; no live lookup of that branch or recursive PR-chain inference replaces integration-result ancestry. Empty/rewritten/patch-equivalent history does not substitute for the tuple.

More than one admissible exact-head PR requires a hint. No-match complete discovery retains `integration-not-proven`. API failures/404 never prove absence or unmerged status. Individually re-read the selected PR after discovery and at every before-recovery and before-destructive boundary; compare all proof fields except observation timestamps, not merely number/head. Re-read repository ID with it. Any field/identity change refuses, even if the new tuple would also qualify. A PR closed collection is not re-scanned at apply: the plan's explicit selected stable PR identity is its authority, with its full tuple freshly verified.

## Tracking advertisement and mapping

Require one selected remote, one canonical fetch URL, exactly one standard `+?refs/heads/*:refs/remotes/REMOTE/*` mapping, no mirror/negative/duplicate/custom/overlapping mappings or unresolved URL/config origins. Bind literal relevant config bytes/origins and normalized mapping into plan fingerprints. Enumerate all local tracking refs and symbolic relations using native typed reads; keep symbolic remote HEAD and its fully resolved target protected, refusing unresolved/cyclic relations. Selected base name/OID and all workspace-used identities remain protected.

Read `GET /repos/OWNER/REPO/branches?per_page=100&page=N` without a protected filter. Validate every unique literal branch name and full OID, bound the full collection, and fingerprint sorted name/OID pairs plus repository ID. Two complete planning advertisements must agree. At each before-recovery and final prepared-reference boundary, obtain a complete new advertisement and repository identity; compare the full fingerprint to the plan (unchanged unrelated branches are part of this conservative snapshot policy). A changed advertisement requires replan, never incremental reinterpretation. The mapped `refs/heads/SUFFIX` must be absent; a present source retains even with a different OID.

Before committing deletion, native mapping/config/target/symbolic protections and complete fresh advertisement must still agree. The local prepared old-OID/no-deref transaction is specified in [tidy-v3](tidy-v3.md). Provider absence cannot prevent later server recreation; disclose sampling. The command never changes server refs, invokes fetch/prune, rewrites config or updates a stale-but-live local tracking OID.

## Injection and failure fixtures

Use deterministic transport doubles with per-request assertions and no real credentials. Cover every required field omitted/null/wrong-type, multiple PRs, fork/repository name reuse, amended tip, missing merge object, rebase/squash/ordinary merge, stacked intermediate-base merges with reachable results and deleted/renamed intermediate branches, nonreachable results, changed original base tuple, truncation/duplicate/empty/last-full pages, malicious Link routing, redirect/compression, error bodies, permission/rate-limit and cancellation. Inject changes between discovery/final sample, after recovery and while the native ref transaction is prepared. Assert no request on offline/unauthorized apply, no API mutation methods, no leaked auth, unchanged native state before effects and preserved recovery after partial failure.
