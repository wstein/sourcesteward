# Data model: Tidy contract v3

This is a new typed contract, not added optional semantics in old v1/v2 records. Unknown fields/enums, malformed identities, duplicate selections, invalid unions and oversized encoded records refuse. All arrays are nonnull. JSON is UTF-8; paths/refnames are literal strings, rendered safely for humans. Limits are specification constants, never caller-controlled authority.

## Result and immutable plan

`V3Result`: schema_version=3; command tidy-plan/tidy-apply; status ok/refused/partial/error; backend git/unknown/ambiguous/jj/gitbutler; plan nullable; boundary; actions[]; diagnostics[]; limitations[]. `boundary` carries complete, network_attempted, freshness=sampled-nontransactional, observed_at and measured/native/HTTP budget counters. Incomplete result has no executable plan. Unsupported backend returns a v3 refusal, not a raw Git attempt.

Budget counters retain actual cumulative consumption on failed observations, including the bounded overrun detection byte specified by the stream contract; they are not clamped to admission limits. In particular, HTTP bytes may equal 32 MiB plus one only in an incomplete, non-`ok`, null-plan result with `network_attempted=true`, 1–128 measured requests and the typed `hosting-evidence-limit` diagnostic. This records the failed bound without increasing the 32 MiB admitted-success limit or permitting a second detection byte. Native/content/framing/stderr counters likewise retain their operation-wide measured values, rather than applying a per-file or per-observation cap to the cumulative report. Budget enforcement remains with the collectors under the stream and online contracts.

`V3Plan`: schema_version, plan_id, digest, policy=`tidy-git-v3`, mode=`local-refs|tracking-refs|owned-retirement|legacy-retirement`, canonical source_path/state_dir, expected native snapshot, exact selected base/ref inputs, online nullable, candidates[], retirement nullable, effects[], recovery_limits[]. Stateless reference observations have no stored ID/digest authority; stored plans use existing random-ID generation. Digest covers canonical typed serialization excluding only its own digest, including expected facts, proof IDs, effects, source/store binding and immutable observation records. It is not a signature or permission.

`Candidate`: action_id, kind=branch/tracking-ref, exact full name/OID, decision delete/retain, reason, proof kind, workspace_paths[], evidence nullable. `ProofEvidence` is a tagged union: native ancestry(target/base OIDs), GitHub merge tuple, or branch-absence(mapping/advertisement). A delete decision requires the exact admitted combination for its mode and complete current guards. Recovery for each action has its own fixed plan-derived ref name and selected target OID.

`OnlineSelection`: fixed host, selected local remote, canonical provider repository ID/node ID/name, remote/config fingerprint, hint mappings, observation tuples/digests, declared budget policy. Store proof fields only, never tokens or raw API text. Observation times are report evidence, not expiry-based authorization; resampling always required.

## Retirement union and manifests

`Retirement`: provenance, exact destination, destination/parent/registration physical identities, native target/head/ref, selected actions, full registration/protection set, user-content policy, complete disk/metadata manifests, sibling facts, integration evidence. `provenance` is exactly one of:

- owned: original creation plan/task/completed-journal identities and digest, exact owned lock; existing verification remains mandatory.
- legacy-completion: operator owner label, explicit completed=true, same-user authority declaration, exact selected path, declared known-active protection set, and observed local identity. No creation plan/task fields; no historical ownership claim.

Retirement `integration` is a `V3CommitProof`, with `oid`, `decision`, `reason`, `proof`, nonnull `workspace_paths[]` and nullable tagged-union `evidence`. It binds the exact target commit and selected integration base without a local reference name, kind or reference-action identity. Attached legacy targets and detached owned/legacy targets use this shape; attached legacy branch identity remains in the retirement target. The original workspace paths must be canonical and unique and remain visible, including the selected checkout. They must agree with the same-commit workspace set in the complete private native registration baseline, without substituted or invented paths. The empty-workspace requirement applies only to a reference candidate selected for reference deletion, not retirement commit evidence. Native ancestry and GitHub merged-head evidence retain their exact existing target/base/repository bindings; branch-absence evidence is not a retirement integration proof.

Physical identity includes canonical path, device/inode, UID/owner capability, type/mode, link count, size, mtime and ctime at native available precision; file entries add full SHA-256 content digest and executable fact. Native identity preserves repository/common/per-worktree directories, object format, HEAD OID and attached branch distinctly. Missing timestamp/owner capability refuses v3 retirement. Known registered/protected paths cannot overlap the target; reference usage protects both branch name and commit identity.

`ContentPolicy` is the recognized version/backend enum, not free numeric limits. V3 manifests permit large user content only under `git-v3`; metadata keeps64 KiB. V2/jj serialized types and validation stay unchanged. Hashes cover complete ordered records and sampled identity/time fields. Fields needed for validation cannot be dropped to fit output; oversize refuses rather than emitting an actionable prefix.

## State namespaces and transitions

Secure private namespaces: `tidy-v3-plans` and `tidy-v3-operations`. Existing legacy namespaces are opened read-only only when original owned provenance requires them. Dispatch checks ID ambiguity across all tidy namespaces before selecting; same ID in multiple namespaces refuses. Old stores/plans are never migrated by a read or retry. State disjointness uses all registered/protected roots, not only selected candidates.

`V3Journal`: version, plan_id/digest, mode, phase, current_expected snapshot, ordered entries, known_effects[], diagnostics[]. Each entry binds action_id, planned and confirmed recovery, phase, outcome and allowed native state delta. A completed legacy action records separate registration/files outcomes even when one native invocation performed both. A reference transaction records prepared/commit-attempted/confirmed-or-unknown states; `commit-attempted` is durable intent written before the native send, not proof the send occurred. Acknowledgment loss cannot be reported as no effect.

After durable commit intent, an explicit native outcome confirming preparation, no COMMIT attempt, no commit and no uncertainty permits `target-prepared/commit-attempted` → `target-prepared/aborted` only in a terminal `incomplete` journal. Exactly one newly appended diagnostic uses code `native-commit-aborted:ACTION_ID` with the exact entry action ID and describes the confirmed abort/no-send outcome. Recovery, entry fields other than transaction, native snapshots, deltas and all other actions remain identical. Derived effects remove only that action's possible-reference-deletion while retaining recovery and native lock history; no replay or continuation is permitted. Cancellation alone, uncertain abort/process completion, attempted send, lost acknowledgment or a crash retains unknown/possible effects. No new native effect follows from a journal marker.

For ordered actions, a `prepared` entry whose recovery attempt has been durably recorded is the active journal phase, including after an earlier action completed. Later untouched `prepared` entries do not replace that active phase. No later entry may record a recovery attempt while an earlier action remains unfinished; both stored-record reads and forward transitions enforce this order. This permits the next action's write-ahead attempt record before any recovery creation, without changing prior actions or advancing native snapshots.

Legal forward states: plan → durable prepared journal → confirmed recovery → optional prepared native reference lock → action complete → complete. Retirement inserts registration complete and files complete. Durability failure before destructive execution stops; failure after any native effect returns partial with retained journal/recovery. Never record complete before exact absence/recovery/source-delta verification.

Retries: complete journal permits read-only postcondition verification and no repeated write; all prepared/incomplete/unknown journals refuse automatic replay. Recreated refs/destinations or changed base/config/protection/evidence invalidate the previous result. Recovery refs remain until separately authorized manual removal; no garbage collection or rollback is implied.

## Validation obligations

New schema fixtures cover all modes/statuses and nullability, exact proof/provenance unions, absent IDs, duplicated actions, unsupported policy, wrong host/base/head, namespace escapes, overflow/unknown fields and manipulated effect lists. Store validation additionally proves digest, private-store binding, native/physical relationships and permitted transition deltas; schema validity alone never authorizes action. Existing v1/v2 schema bytes/fixtures, default CLI output and native jj paths are regression invariants.
